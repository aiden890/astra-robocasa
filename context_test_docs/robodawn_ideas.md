# RoboDawn에서 가져올 아이디어

작성일: 2026-10-06. 출처: [논문 arXiv 2609.22966](https://arxiv.org/abs/2609.22966), 코드 `/data/RoboDawn` (커밋 9247f36, `harness/`).

## 1. RoboDawn 요약

- **핵심 아이디어:** 학습하지 않은 VLM(GPT-6 Astra 등)이 "왼팔 x로 10cm 이동", "그리퍼 닫기" 같은 사람이 이해하기 쉬운 명령으로 로봇을 조작합니다. 과제 시연 1개를 프롬프트에 넣어 주는 것(in-context learning)만으로 성능이 크게 오릅니다.
- **RoboTwin 2.0 (Astra):** 시연 없이 53.2%, 시연 1개로 73.6%. 같은 벤치마크로 학습한 π0.5는 46.0%입니다.
- **RoboDojo (Astra):** 시연 없이 35.67%, 시연 1개로 47.17%.

## 2. 지금 우리 방식과 RoboDawn 비교

| 항목 | 지금 astra-robocasa | RoboDawn |
|---|---|---|
| 모델 출력 | 12차원 컨트롤러 값(-1~1)을 그대로 출력하고, 같은 값을 최대 8스텝(0.4초) 반복 | `left move z -5`처럼 cm·도 단위 명령을 한 번에 1~4개 |
| 명령 실행 | 1스텝짜리 행동 몇 번 | 명령 하나가 목표 자세까지 계획된 움직임 한 번이고, 로봇이 멈출 때까지 실행 |
| 기준점 | 손목(컨트롤러 기준) | 손가락 끝 중심(GIP) |
| 한 판의 모델 호출 수 | 수백 번 (PrepareCoffee 약 450번) | 10~45번 |
| 실행 결과 알려주기 | 없음 | 성공/실패, 실제 이동 거리, 남은 오차, "손가락 사이에 물체가 있음" |
| 이미지 | 256px 원본 그대로 | 10cm 격자, 손끝 표시, 축 표시를 그려 넣고 위에서 보는 시점 추가 |
| 응답 형식 | `action`, `repeat`, `reason` | `scene`, `progress`, `memory`, `plan`, `commands` |
| 기억 | 최근 행동 8개(숫자) | 모델이 매 턴 다시 쓰는 메모 + 최근 12턴 명령과 결과 + 잡은 높이 |
| 시연 | 없음 | 명령 입문(primer) 1개 + 해당 과제 시연 1개 |
| reasoning 강도 | low | Astra는 high |
| 상태 정보 | 물체 위치를 포함한 관측값 전체 | 로봇 손끝 위치, 방향, 그리퍼 열림 정도만 (물체 위치는 안 줌) |
| 로봇·환경 설명 | 컨트롤러 설정 JSON 그대로 | 좌표계, 닿는 범위(실측), 카메라, 그리퍼, 팁을 사람이 정리한 프로필 YAML |

## 3. 가져올 아이디어 (중요한 순서)

논문의 제거 실험(Gemini, 시연 없음, 기준 47.0%)에서 각 요소를 뺐을 때의 성공률을 괄호에 적었습니다.

1. **명령 문법과 끝까지 실행하는 실행기.** 모델은 방향과 거리만 정하고, 실제 움직임은 실행기가 처리합니다. 이번 개선의 핵심입니다.
2. **이미지 위 격자와 손끝 표시** (격자 제거 시 32.4%). README 기준으로 위치 추정 오차가 5~10cm에서 2~3cm로 줄었습니다.
3. **추론 켜기와 구조화된 응답** (추론 제거 시 34.8%). 응답에 장면, 진행 상황, 계획을 먼저 쓰게 하고 명령은 마지막에 둡니다.
4. **사실대로 알려주는 실행 결과.** 실패하면 "팔이 움직이지 않았다" 또는 "일부만 움직였다"고 알려줍니다. 그리퍼는 멈출 때까지 기다린 뒤 열림 정도를 읽습니다.
5. **메모장 기억.** 모델이 매 턴 메모를 새로 씁니다. 기계가 기록한 이력만 길게 주는 것은 효과가 없었다고 합니다.
6. **시연 1개(ICL).** 전문가 궤적을 명령 순서로 바꾸고, 핵심 장면(그리퍼나 방향을 바꾸는 순간)의 이미지를 최대 16장까지 함께 줍니다. 효과가 가장 큽니다(47.0%에서 62.2%로, Astra는 53.2%에서 73.6%로). 시연은 4개까지 늘리면 조금 더 좋아지고, 8개는 오히려 떨어집니다.
7. **명령 입문(primer)** (제거 시 44.0%). 깨끗한 장면에서 명령 하나하나가 무엇을 하는지 6단계로 보여줍니다.
8. **`done`을 말해도 바로 끝내지 않기.** 성공 판정이 나지 않았으면 "아직 안 끝났다"고 알려주고 계속 진행합니다.

## 4. RoboCasa에 맞게 바꿔야 할 점

- **이동 로봇:** PandaOmron은 바퀴로 움직입니다. RoboDawn은 고정된 탁자 앞의 양팔 로봇이라 이동 명령이 없습니다. `base move forward|left <cm>`, `base rotate <deg>`를 추가해야 합니다. 몸통 높이 조절(`torso`)도 필요한지 확인합니다.
- **좌표계:** 주방마다 방향이 달라서 월드 좌표 대신 로봇 기준 좌표(앞, 왼쪽, 위)가 더 직관적입니다.
- **실행기:** RoboTwin은 경로 계획기(cuRobo)를 씁니다. RoboCasa에는 OSC 컨트롤러가 있으니, 목표 손끝 자세까지 반복해서 제어하고 오차가 작아지면 멈추는 방식으로 만듭니다. 이때 쓰인 시뮬레이터 스텝은 과제의 스텝 예산에서 차감합니다.
- **격자:** RoboCasa에는 탁자가 하나만 있는 게 아니라서, 로봇 앞 조리대 높이에 로봇 기준 격자를 그립니다. 카메라 투영 행렬은 robosuite `camera_utils`로 구합니다.
- **난이도:** 서랍장 손잡이 잡기(OpenCabinet), 젓기(StirVegetables), 팬 기울이기(PanTransfer)처럼 회전과 정밀한 조작이 필요한 과제가 많습니다. 논문도 회전과 정밀 조작이 약점이라고 밝히고 있습니다.
- **시연 데이터:** `/data/code/robocasa/datasets/v1.0`에 5개 과제의 사람 시연(LeRobot 형식)이 있습니다. 위치는 아래와 같습니다.

  | 과제 | 시연 위치 |
  |---|---|
  | PrepareCoffee, StirVegetables, OpenCabinet, PickPlaceSinkToCounter | pretrain |
  | PanTransfer | target에만 있음 |

  각 시연에는 다음이 들어 있습니다: 로봇 위치·방향, 로봇 기준 손끝 위치·방향, 그리퍼, 행동, 카메라 영상 3개, 장면 파일(`model.xml.gz`, `ep_meta.json`). 손끝 위치와 그리퍼 변화를 기준으로 궤적을 몇 개의 지점으로 줄이고, 그 지점들을 명령 순서로 바꾸면 시연을 만들 수 있습니다. 평가 장면과 같은 장면의 시연은 쓰지 않습니다.
- **호출 방식:** RoboDawn은 OpenAI 호환 API를 직접 부르지만, 우리는 구독 계정으로 `codex exec`를 씁니다. 그래서 시스템 프롬프트를 마음대로 정할 수 없고, 모든 내용을 사용자 입력과 `--image`로 넣어야 합니다. 캐시 할인을 받으려면 바뀌지 않는 부분(프로필, 입문, 시연)을 앞에 두어야 합니다. 이미지와 글자가 어떤 순서로 들어가는지, 그리고 캐시가 실제로 되는지는 확인이 필요합니다.

## 5. 비용·시간 예상 (확인 전)

- **턴 수:** 한 판에 최대 45턴입니다(논문 설정).
- **턴당 시간:** reasoning high라 지금(약 11초)보다 길어져 20~40초로 예상합니다.
- **한 판 시간:** 15~30분입니다.
- **턴당 입력:** 시연 이미지가 포함되어 수만 토큰입니다. 대부분은 매 턴 같은 내용이라 캐시 단가($1/1M)가 적용될 것으로 예상합니다.
- **비교:** 지금 방식의 PrepareCoffee 한 판은 약 450번 호출, 약 $26입니다. RoboDawn 방식은 호출 수가 10분의 1 수준이라 비용이 더 낮을 수도 있습니다. 첫 실행에서 측정합니다.

## 6. 구현 순서 (제안)

1. **실행기와 명령 문법:** 시뮬레이터 워커에 `command` 요청을 추가합니다. move, rotate, point, gripper, home, base, wait를 받아 끝까지 실행하고 결과를 돌려줍니다. RoboDawn의 `core/commands.py`를 기반으로 base 명령을 더합니다.
2. **에이전트 루프:** RoboDawn의 `mllm_agent.py`, `prompts.py`, `memory.py` 구조를 `codex exec` 호출에 맞게 옮깁니다. 기존 Inspect Robots 경로는 비교용 기준선으로 남겨 둡니다.
3. **RoboCasa 프로필과 이미지 표시:** 프로필 YAML을 만들고, 이미지에 격자와 손끝 표시를 그립니다. 팔이 닿는 범위는 실제로 측정해서 적습니다.
4. **시연 없이 시험:** OpenCabinet(가장 짧은 과제)으로 동작을 확인한 뒤 5개 과제를 돌립니다.
5. **명령 입문과 과제 시연 만들기:** 사람 시연을 명령 순서로 변환하고, 핵심 장면 이미지를 뽑고, 각 단계의 의도는 VLM이 사후에 써 넣습니다.
6. **시연 1개로 5개 과제 실행.** 매 실행의 토큰 사용량, 비용 추정치, 영상은 [README.md](README.md) 3절 규칙대로 남깁니다.

## 7. 정해야 할 것

- **물체 위치를 줄지:** 논문처럼 주지 않을지, 지금처럼 줄지 정해야 합니다.
- **reasoning 강도:** high(논문)와 low(비용 절약) 중 고릅니다.
- **기준선:** 지금 방식(12차원 숫자 출력)도 같은 5개 과제로 돌려서 비교 기준으로 쓸지 정합니다.
