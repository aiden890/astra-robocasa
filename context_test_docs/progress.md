# 진행 기록: astra_robodawn

계획은 [implementation_plan.md](implementation_plan.md)에 있습니다. 단계가 끝날 때마다 이 파일에 무엇을 했고 어떻게 검증했는지 적습니다.

## 실행 규칙 (사용자 지시, 2026-10-06)

- **시뮬레이터:** 항상 1개만 돌립니다. 같은 서버에서 GPU 학습이 돌고 있기 때문입니다.
- **reasoning effort:** `low`로 고정합니다.
- **Astra 실행 횟수:** P4에서 1번(OpenCabinet, 0-shot), P6에서 과제별 1번씩 5번(1-shot)으로 **총 6번**입니다. 이 6번 말고는 Astra를 호출하지 않습니다.
- **실행 기록:** Astra 실행마다 아래를 모두 파일로 남깁니다.
  - LLM 입력(텍스트, 이미지)
  - reasoning(받을 수 있는 범위)
  - 출력
  - 중간 결과
  - 영상
  - seed, 처음 상태, 장면 asset 위치 (replay용)

### P1: 명령 문법과 실행기 (완료)

**만든 파일** (`plugins/inspect-robots-robocasa-astra/src/robocasa_astra/astra_robodawn/`)

| 파일 | 내용 |
|---|---|
| `commands.py` | 명령 문법과 해석기. 로봇 기준 방향(forward/back/left/right/up/down), rotate, point, gripper, base, home, wait, done. 크기 제한: 이동 20 cm, 회전 90도, 바퀴 50 cm, 바퀴 회전 45도 |
| `executor.py` | 명령 하나를 끝까지 실행합니다. 손끝(`gripper0_right_grip_site`)과 로봇 기준점(`mobilebase0_center`)을 직접 읽고, OSC 입력을 매 스텝 계산합니다. 도달, 진전 없음, 최대 스텝 중 하나가 되면 멈추고 결과를 사실대로 돌려줍니다. 관절 한계와 접촉도 구분해서 알려줍니다. |
| `recorder.py` | 20fps MP4(카메라 3대 + 자막)와 replay 파일(scene.json, ep_meta.json, initial_state.npz, model.xml.gz, actions.npy/jsonl, command_segments.json, final_state.npz) |

**만든 스크립트:**
- `scripts/robocasa-astra/check_executor.py`: 모델 없이 실행기 검증
- `scripts/robocasa-astra/replay_run.py`: 기록된 실행을 다시 실행하고 마지막 상태 비교

**확인한 사실**
- **로봇 기준 좌표계:** `robot0_base_to_eef_pos`와 OSC 입력 좌표계가 같습니다. x는 앞, y는 왼쪽입니다.
- **높이:** 바닥 기준으로 표시합니다. 로봇 기준점은 높이 70 cm이고, 처음 손끝은 (앞 25.6, 왼쪽 0, 높이 129) cm에서 손가락이 거의 아래를 향합니다.
- **바퀴 속도 명령:** 현재 로봇 기준(앞, 왼쪽, 회전)으로 해석됩니다(`LegacyMobileBaseJointVelocityController`).
- **카메라 이미지:** `create_env`가 `use_camera_obs=True`라서 매 스텝 관측값에 카메라 3대(256px)가 들어옵니다. 영상은 이것을 그대로 씁니다.
- **스텝 예산:** `create_env`가 `ignore_done=True`라서 예산은 실행기가 직접 지킵니다.
- **OpenCabinet 장면 (layout 1, style 1, seed 771001):** 조리대 위 벽에 달린 양문 수납장(HingeCabinet)이고, 지시문은 "Open the cabinet doors."입니다. 문 2개가 모두 90% 이상 열려야 성공입니다.

**처음 시도에서 발견해서 고친 것**
1. **OSC가 흔들림:** 한 스텝에 최대 5 cm로 밀면 일부 자세에서 OSC가 흔들려 뒤로 밀렸습니다. 최대 2.5 cm/스텝(`ARM_MAX_INPUT = 0.5`)으로 줄였습니다.
2. **원인 구분 안 됨:** 실패 원인을 구분하지 못했습니다. 관절이 한계(2% 이내)에 닿으면 "자세 한계", 아니면 "접촉"이라고 알리게 했습니다.
3. **멀리서 home 복귀 실패:** 멀리 간 뒤 home으로 돌아오는 데 60스텝이 모자랐습니다. 명령당 최대 스텝을 80으로 늘렸습니다.
4. **replay 불일치:** 모델 XML과 초기 상태를 복원하는 방식(`--mode state`)은 컨트롤러가 새로 만들어져서 2,539스텝 뒤 상태가 달랐습니다(최대 차이 3.15). 같은 task와 seed로 장면을 다시 만들고 행동을 재실행하는 방식(`--mode seed`, 기본값)을 쓰기로 했습니다.

**검증 결과** (`runs/p1-executor-check/`, 모델 호출 없음, 시뮬레이터 1개)

| 명령 | 결과 | 스텝 |
|---|---|---|
| move up/down/back/left/right 10 | 도달 | 15~18 |
| move forward 10 | 도달 | 25 |
| move forward 20 (손가락 아래) | 10 cm에서 멈춤. 손목이 벽 수납장 밑면에 닿음 | 26 |
| rotate yaw/pitch/roll ±20~30 | 도달 | 7~11 |
| point down45 / down | 도달 | 9 / 16 |

| gripper close (빈손) | "nothing between them" | 21 |
| gripper open | 열림 | 4~21 |

**닿는 범위** (home에서 5 cm씩, 이 장면 기준)
- **손가락 아래:** 앞으로 x 약 50까지(그다음 벽 수납장에 접촉). 왼쪽으로 y 약 67까지. 몸 가까이에서 내려가면 높이 약 92 cm에서 팔꿈치 관절 한계.
- **손가락 수평(point forward):** 앞으로 x 약 92까지, 좌우 y −54 ~ +66.

**replay 검증:** `replay_run.py --mode seed`로 2,539스텝을 다시 실행했더니 초기 상태 차이 0.0, 마지막 상태 차이 **0.0**이었습니다(정확히 재현).

**단위 테스트:** 58개 통과(명령 문법 21개, 회전 계산 등 포함).

**스텝 예산에 대한 의미:** 10~20 cm 이동 명령 하나가 15~30스텝을 씁니다. OpenCabinet 예산 1,050스텝이면 명령 40~60개 정도를 쓸 수 있습니다. 바퀴 회전은 20도에 약 67스텝으로 느린 편입니다.

- **발견해서 고친 것:**

| `run.py` | 실행 진입점. 아래 안전장치 포함 |

**Codex 설정 확인** (로그인 없는 빈 설정 폴더로 검사, 모델 호출 없음)
- `model_reasoning_summary`, `developer_instructions`, `model_instructions_file`는 유효한 키입니다.
- `model_supports_reasoning_summaries`, `base_instructions`, `experimental_instructions_file`는 존재하지 않는 키입니다.
- 결정: 시스템 프롬프트를 `model_instructions_file`로 넣어 Codex 기본 코딩 지침(약 7.5K 토큰)을 대체합니다. RoboDawn처럼 자체 시스템 프롬프트를 쓰는 셈이고, 매 턴 같은 앞부분이라 캐시에도 유리합니다.
- reasoning 요약은 `model_reasoning_summary="detailed"`로 요청합니다. 서버가 거부하면 요약 없이 한 번 다시 시도하고, 그 사실을 기록합니다.

**Astra 안전장치** (`run.py`)
- `--scripted`(모델 없음)와 `--allow-astra`(실제 모델) 중 하나를 반드시 골라야 합니다.
- 실제 실행은 `runs/astra_ledger.jsonl`에 기록하고, 6번을 넘으면 실행을 거부합니다.
- 실제 실행에서는 `--max-turns`로 턴 수를 바꿀 수 없습니다.

**검증 결과**
- **단위 테스트:** 65개 통과. 가짜 시뮬레이터와 정해진 응답으로 성공 종료, 잘못된 명령, `done` 처리, 파일 생성을 확인했습니다.
- **정해진 응답으로 실제 시뮬레이터 실행 (`runs/p3-dryrun-opencabinet/`):** OpenCabinet 5턴, 228스텝.
  - 실행 폴더에 config.json, system_prompt.md, response_schema.json, episode_start.json, trace.jsonl, calls/turn001~005, turns/(턴별 이미지 3장 + final), memory.json, summary.json, video.mp4(228프레임), replay/, sim.log가 모두 생겼습니다.
  - 턴 4 프롬프트를 직접 읽어서 지난 결과, 상태, 메모, 기록, 잡은 높이, 이미지 목록이 맞게 들어간 것을 확인했습니다.
  - replay `--mode seed`: 마지막 상태 차이 0.0.
  - 장부(ledger)는 생기지 않았습니다. Astra 호출이 없었다는 뜻입니다.
- **발견해서 고친 것:**
  - 손가락이 벽 수납장 밑면에 막혀 0.08에서 멈췄는데 "아마 잡았음"이라고 표시됐습니다. 문구를 "물체가 손가락 사이에 있거나, 손가락이 어떤 면에 눌려 막힘. 손목 카메라로 확인"으로 바꿨습니다.

**P4 전에 할 일**

### P4 준비: 명령 입문(primer) 만들기와 실행기 수정 (완료, 모델 호출 없음)

**primer** (`assets/demos/primer/`, `demo_builder.py primer`)
- **장면:** 평가 장면이 아닌 주방(PickPlaceCounterToSink, layout 11 / style 11, seed 771101)에서 우리 실행기로 실제로 실행했습니다.
- **구성:** 8단계이고, 단계마다 실행 전 왼쪽 overview 이미지(256px), 상태, 설명, 명령, 측정된 효과가 들어 있습니다.
  1. move up/forward
  2. move left
  3. rotate yaw
  4. point forward
  5. point down + move down
  6. 빈손으로 gripper close (0.00) → open
  7. base right
  8. 조리대(싱크 가장자리)에 막혀 실패하는 예시
- 8장의 이미지와 효과 문구를 직접 확인했습니다.

**primer를 만들다 발견해서 고친 실행기 문제**
1. **손가락 닫힘 축이 틀렸음:** 상태의 finger axis를 손끝 기준점 y축으로 보고하고 있었습니다. 손가락 몸체 위치로 확인해 보니 실제로는 **x축**(처음 자세에서 로봇 좌우)으로 닫힙니다. 고쳤습니다.
2. **`point` 프리셋:** "현재 자세에서 손가락 방향만 최소 회전"하던 방식을, RoboDawn처럼 **고정된 완전한 자세**로 바꿨습니다. 앞선 yaw 회전이 남아 관절 한계에 걸리던 문제가 없어졌습니다. 세 프리셋 모두 손가락이 좌우로 닫힙니다.
3. **진전 판정이 너무 빨랐음:** 회전 중에는 손끝이 잠깐 처지는데, 위치와 각도를 합친 하나의 오차로 판정하다 보니 "진전 없음"으로 잘못 멈췄습니다(예: 높은 위치에서 point down이 19도에서 멈춤). 위치(2 mm)와 각도(1도)를 **따로** 추적하도록 고쳤고, 같은 명령이 32스텝 만에 도달했습니다. 접촉과 관절 한계가 없다는 것도 시뮬레이터 접촉 목록으로 확인했습니다.
4. **큰 회전 나누기:** 45도보다 큰 회전은 45도 이하 구간으로 나눠 차례로 따라가게 했습니다.
5. **`point forward`의 조건:** 손끝이 몸에서 25 cm(처음 자세)일 때는 관절 한계로 안 되고, 앞으로 10~15 cm 옮기면 됩니다. 이 내용을 로봇 설명서 팁에 넣었습니다.
6. **이미지 경로:** 실행 폴더를 절대 경로로 바꿨습니다. Codex는 빈 폴더에서 실행되기 때문에, 상대 경로면 이미지를 못 찾습니다.
7. **프롬프트 문구:** 작업면 높이를 끼워 넣는 부분이 어색한 영어가 되던 것을 고쳤습니다.

**재검증**

### P5: 과제 시연 만들기 (진행 중)

**방식** (`expert.py`, `demo_builder.py task <Task>`, `assets/demo_plans/<Task>.json`)
